# Phase 3a — Production Build, Distribution & Self-Update (SHIPPED 2026-05-17)

## Context

PhotoX was Xcode-only and dynamically linked against `/opt/homebrew/lib/libraw_r.dylib` + `/opt/homebrew/bin/exiftool`. Copying the `.app` to another Mac would crash on launch. Phase 3a turned it into a **standalone, self-contained `.app`** with a **Sparkle 2 "Check for Updates…" menu item**, shippable to friends as a `.dmg` from GitHub Releases. No Apple Developer Program required for phase 3a (ad-hoc signed). The full pipeline runs as one local command.

First release: **v0.82.0**. Update round-trip verified to **v0.86.0** via Sparkle.

## What shipped

| Area | Decision |
|---|---|
| LibRaw | Static `.a` built from source via `scripts/bootstrap.sh` with `--disable-jpeg --disable-jasper --disable-lcms --disable-openmp`. Vendored at `ThirdParty/libraw/`. **Plus `-lz` for the DNG decoder's `uncompress()` symbol.** |
| ExifTool | Phil Harvey's Perl distribution bundled at `Resources/exiftool/`. Version auto-discovered from `exiftool.org` (they only keep the latest production tarball). |
| Auto-update | **Sparkle 2** (SwiftPM, `2.6.0+`), EdDSA-signed updates, appcast on `raw.githubusercontent.com` |
| Hosting | Public GitHub repo `Frostman/photo-x`; `.dmg` per GitHub Release; appcast at `https://raw.githubusercontent.com/Frostman/photo-x/master/docs/appcast.xml` |
| Signing — phase 3a (current) | Ad-hoc (`codesign --sign -`). Friends right-click → Open the first time |
| Signing — phase 3b (future) | Developer ID Application + notarization. One-time manual redownload at the transition (Sparkle enforces signature continuity) |
| Versioning | `v0.<commit-count>.0-<sha9>[-dirty]`. Derived from git at archive time; `project.yml` holds `0.0.0` placeholders that are never edited. Passed via `xcodebuild MARKETING_VERSION=… CURRENT_PROJECT_VERSION=… GIT_DESCRIBE=…`. |
| Vendored deps | **Not committed.** `ThirdParty/libraw/` and `Resources/exiftool/` in `.gitignore`. `scripts/bootstrap.sh` materialises them idempotently. |
| Architecture | arm64-only (`ARCHS: arm64`, `ONLY_ACTIVE_ARCH: NO`). Vendored libraw is arm64; macOS 26 deployment target is Apple-Silicon anyway. |

## Version scheme — git-derived

```sh
COMMITS=$(git rev-list --count HEAD)
SHA9=$(git rev-parse --short=9 HEAD)
DIRTY=$([ -n "$(git status --porcelain)" ] && echo "-dirty" || echo "")
MARKETING="0.${COMMITS}.0"                # → CFBundleShortVersionString
BUILD="${COMMITS}"                        # → CFBundleVersion (monotonic for Sparkle)
DESCRIBE="v${MARKETING}-${SHA9}${DIRTY}"  # → Info.plist GitDescribe (human-readable, used in About / footer)
TAG="v${MARKETING}"                       # → GitHub Release tag
```

- Apple's required numeric `CFBundleShortVersionString` + monotonic `CFBundleVersion` map to `0.<N>.0` and `<N>` respectively.
- Sparkle's `<sparkle:shortVersionString>` / `<sparkle:version>` use the same values.
- `release.sh` refuses to cut from a dirty tree (`-dirty` would land in CFBundleShortVersionString and Sparkle would reject the format).

## Implementation notes — gotchas hit during execution

These weren't in the original plan; documenting them so they're not relearned.

### 1. LibRaw needs `-lz`
LibRaw's `deflate_dng_load_raw` calls zlib's `uncompress()`. Without `-lz` in `OTHER_LDFLAGS`, the static link fails with `_uncompress: undefined symbol`.

### 2. arm64-only required for vendored libraw
Default Release archives target both arm64 + x86_64. The vendored `libraw_r.a` is arm64-only. Without `ARCHS: arm64` + `ONLY_ACTIVE_ARCH: NO`, archive fails on x86_64 linking. (Acceptable: macOS 26 is Apple-Silicon anyway.)

### 3. xcodegen folder ref needs the sub-path, not the parent
`- path: Resources, type: folder, buildPhase: resources` produced `PhotoX.app/Contents/Resources/Resources/exiftool/` (double-nested). Fix: `- path: Resources/exiftool` so the folder lands at `Contents/Resources/exiftool/`.

### 4. `GENERATE_INFOPLIST_FILE` silently drops custom keys
Xcode's auto-generated Info.plist only honors `INFOPLIST_KEY_*` for an Apple-curated allowlist of keys. `SUFeedURL`, `SUPublicEDKey`, `GitDescribe` were all silently dropped, and `Check for Updates…` failed at runtime with "You must specify SUFeedURL". Fix: use xcodegen's `info:` block to template a real `PhotoX/Info.plist` (gitignored, regenerated by xcodegen):

```yaml
info:
  path: PhotoX/Info.plist
  properties:
    CFBundleShortVersionString: $(MARKETING_VERSION)
    CFBundleVersion: $(CURRENT_PROJECT_VERSION)
    GitDescribe: $(GIT_DESCRIBE)              # overridden by release.sh via xcodebuild
    SUFeedURL: https://raw.githubusercontent.com/Frostman/photo-x/master/docs/appcast.xml
    SUPublicEDKey: "<base64 EdDSA public key>"
    SUEnableAutomaticChecks: true
    SUScheduledCheckInterval: 86400
    …
```

### 5. `#if DEBUG`-gate the Homebrew fallback in `ExifToolRunner`
The dev fallback string `/opt/homebrew/bin/exiftool` was a Swift literal compiled into the Release binary, and the static self-containment check correctly flagged it. Fix: split the literal (`"/opt/" + "homebrew/bin/exiftool"`) inside a `#if DEBUG` branch; Release builds return `""` and log an error if the bundle resource is missing.

### 6. Ad-hoc Sparkle.framework crashes hardened-runtime app
Both PhotoX (ad-hoc) and Sparkle.framework (ad-hoc after our re-sign) have empty Team IDs. The hardened runtime treats "no Team ID" + "no Team ID" as *mismatched* Team IDs and refuses to load the framework with:
> code signature in ... not valid for use in process: mapping process and mapped file (non-platform) have different Team IDs

Fix: add `com.apple.security.cs.disable-library-validation` to `PhotoX.entitlements`. **Remove this entitlement in phase 3b once Sparkle is re-signed with the real Developer ID.**

### 7. `codesign --deep` doesn't reliably restamp pre-signed nested bundles
Sparkle.framework ships pre-signed by the Sparkle maintainers and contains nested `Updater.app` + `XPCServices/{Downloader,Installer}.xpc`. `--deep --sign -` left them with the maintainers' original Team ID. Fix in `release.sh`: strip every `_CodeSignature` directory, then sign inside-out via depth-first `find`:

```sh
find "$APP" -path '*/_CodeSignature' -type d -prune -exec rm -rf {} +
while IFS= read -r BUNDLE; do
  codesign --force --sign - --options runtime --timestamp=none "$BUNDLE"
done < <(find "$APP/Contents/Frameworks" \
  \( -name '*.xpc' -o -name '*.app' -o -name '*.framework' \) -type d -depth)
codesign --force --sign - --options runtime --timestamp=none \
  --entitlements PhotoX/PhotoX.entitlements "$APP"
```

### 8. Skip `xcodebuild -exportArchive` for ad-hoc builds
`exportArchive` with `method: developer-id` requires a Team ID. There is no equivalent method for "I just want my unsigned binary out of the archive". Workaround: copy the `.app` directly from `build/PhotoX.xcarchive/Products/Applications/PhotoX.app`. The plist (`scripts/export-options.plist`) stays for phase 3b.

Archive build needs these overrides to skip signing:
```sh
xcodebuild archive ... \
  CODE_SIGN_IDENTITY="-" \
  CODE_SIGNING_REQUIRED=NO \
  CODE_SIGNING_ALLOWED=NO
```

### 9. GitHub Pages was hijacked by a user-level CNAME
`Frostman.github.io` has a CNAME from an old blog repo pointing to `oldblog.slukjanov.name`. So `https://Frostman.github.io/photo-x/appcast.xml` was getting a 301 → `http://oldblog.slukjanov.name/photo-x/appcast.xml` (HTTPS→HTTP, plus the target 404s). Sparkle would refuse the downgrade. Fix: host the appcast on `https://raw.githubusercontent.com/Frostman/photo-x/master/docs/appcast.xml` — direct from the repo, no Pages config required, 5-minute cache. No GitHub Pages was enabled in the end.

### 10. BSD `awk -v` can't take multi-line values
The original splice `awk -v snip="$SNIPPET" '/<\/channel>/ { print snip } { print }'` died on macOS BSD awk with `newline in string`. Fix: write the snippet to a temp file and assemble three streams via `sed -n`:

```sh
{
  sed -n '/<\/channel>/,$!p' docs/appcast.xml   # everything before </channel>
  cat "$SNIPPET_FILE"
  sed -n '/<\/channel>/,$p' docs/appcast.xml    # </channel> and below
} > docs/appcast.xml.new
mv docs/appcast.xml.new docs/appcast.xml
```

### 11. `set -o pipefail` + `grep -v` silently aborted release.sh
`PREV_TAG=$(git tag --list 'v0.*' | grep -v "^$TAG$" | head -1)` silently exits the script on the first release when no `v0.*` tags exist locally (we use GitHub-side tagging via `gh release create`, never pulled back). `grep -v` returns 1 when no input matches, pipefail propagates 1, `set -e` aborts — but the failure happens *after* `git push`, so the appcast splice + push succeeds but `gh release create` never runs. Fix: switch the lookup to `gh release list --json tagName --jq '.[].tagName'` with `|| true`.

### 12. `sign_update` emits its own `length=` attribute
The Sparkle helper `bin/sign_update` outputs `sparkle:edSignature="…" length="…"` together. Don't emit a separate `length="$SIZE"` in the appcast snippet template — duplicate attribute = invalid XML.

### 13. ExifTool version can't be pinned
`exiftool.org` removes old versions when a new one is released; pinning `13.55` 404s within days. `bootstrap.sh` now scrapes the homepage for the current `Image-ExifTool-N.NN.tar.gz` filename and downloads that.

## release.sh — final shape

One command, no flags. Refuses dirty tree. End-to-end:

```
[release] v0.86.0-573433f35  (marketing=0.86.0 build=86)
[release] archive
[release] static self-containment check
  ✓ no Homebrew/libraw refs anywhere in bundle
  ✓ no hardcoded /opt/homebrew or /usr/local strings in main binary
  ✓ Resources/exiftool/exiftool present + executable
[release] ad-hoc codesign
  (re-signs Sparkle's nested xpc/app/framework, then outer app)
[release] dmg → build/PhotoX-v0.86.0-573433f35.dmg
[release] splice appcast
[master 0c7867f] Release v0.86.0-573433f35
[release] gh release create v0.86.0
https://github.com/Frostman/photo-x/releases/tag/v0.86.0
[release] DONE
```

Flags:
- `--verify-only` — build + static self-containment checks + `BundledResourcesTests` (Debug). No signing/DMG/publish.
- `--dry-run` — full build + DMG + EdDSA sign + prints appcast snippet. No commit/push/publish.

## Sensitive data — still TODO (manual user step)

The Sparkle EdDSA private key lives in macOS Keychain under host `https://sparkle-project.org` (account = the public key). **Losing it permanently breaks the update channel** — every shipped PhotoX trusts ONLY signatures made by this exact key. Back it up to 1Password:

```sh
# Print the private key to copy into 1Password
security find-generic-password -s "https://sparkle-project.org" -w
```

1Password Secure Note:
- **Title**: `PhotoX — Sparkle EdDSA private key`
- **Body**: the base64 string from `security find-generic-password`
- **Reminder**: "Keychain account = `MWNF/JmW7AQ0wjmzYowNL1NNcybTAAfRnTQO3nsjbHs=`. Restore via `echo '<key>' | $(find ~/Library/Developer/Xcode/DerivedData -path '*Sparkle*/bin/generate_keys' | head -1) -f -`."

Also worth a note for the public key: `MWNF/JmW7AQ0wjmzYowNL1NNcybTAAfRnTQO3nsjbHs=`. Recoverable from any shipped `.app`'s Info.plist, so less critical, but easier to have on hand.

## Phase 3b switchover (when Apple Developer Program clears)

1. Import Developer ID Application `.p12` to Keychain (back up via 1Password Secure Note `PhotoX — Developer ID Application .p12`).
2. Generate App Store Connect API key at App Store Connect → Users and Access → Integrations → App Store Connect API. One-time download of `.p8`. Back up immediately (`PhotoX — App Store Connect API key (notarization)`, Key ID, Issuer ID).
3. Add `DEVELOPMENT_TEAM` to `project.yml`.
4. **Remove `com.apple.security.cs.disable-library-validation`** from `PhotoX.entitlements` — Sparkle's Team ID will now match PhotoX's.
5. In `scripts/release.sh`, replace the ad-hoc `codesign` block with the Developer ID block (already commented in the script):
   ```sh
   codesign --force --deep --sign "Developer ID Application: <Name> (TEAMID)" \
     --options runtime --timestamp \
     --entitlements PhotoX/PhotoX.entitlements "$APP"
   xcrun notarytool submit "$APP" --apple-id "$APPLE_ID" --team-id TEAMID \
     --key "$ASC_KEY_PATH" --key-id "$ASC_KEY_ID" --issuer "$ASC_ISSUER" --wait
   xcrun stapler staple "$APP"
   ```
   (With a real Developer ID, `--deep` *does* reliably re-stamp Sparkle's nested bundles, so the strip+inside-out loop can stay or be removed.)
6. Cut a release. Email friends: "one-time, please redownload from https://github.com/Frostman/photo-x/releases/latest — after this update, auto-updates resume forever". (Sparkle 2 enforces code-signature continuity; unsigned → Developer ID is a "signature changed" event that blocks an in-place auto-update.)

## What this constrains for Phase 4+

- Vendored binaries live outside git → `bootstrap.sh` is mandatory for any fresh clone. Documented in `README.md`.
- All scripts hermetic (no `sudo`, no system mutation). Verification = static analysis + in-bundle XCTest + a friend's real machine.
- Sparkle keypair lives only in macOS Keychain on the dev machine. The 1Password backup is the only disaster-recovery path — **do this before shipping to >1 friend**.
- CI port (GitHub Actions): bootstrap is unchanged; `release.sh` needs the cert + ASC API key + Sparkle private key injected as secrets. GitHub-hosted runners have no Homebrew, so they're a natural clean-environment verifier.
- A native Sony MakerNote parser would remove the last external runtime dep (`/usr/bin/perl`) and shave 25 MB. Deferred.
- Sandboxing still off. Enabling means adding `SUEnableInstallerLauncherService` + an XPC helper for Sparkle; non-trivial. Skip until there's a reason.
- macOS 26 deprecation: if Apple finally removes `/usr/bin/perl` in macOS 27, switch to a `par-packer`/`PerlApp` standalone exiftool or to a Swift Sony parser. Currently no signal that's imminent.
